## 三、暴力抽射（Brutal Shot）

### 1. 定位

- 挂在角色身上的 Buff，不再使用独立的 `BrutalShotComponent`。
- 持有期间，该角色踢**普通泡泡**时不再走普通 8 格踢飞，而是走暴力抽射结算。
- 足球（带 `FootballComponent` 的泡泡）不进入暴力抽射分支，仍走足球自己的踢球逻辑。
- 代码里不限制必须是 Boss：任何角色带上 `BuffBrutalShot` 都能触发；占位驱动只给足球图的 AI Boss 挂。

### 2. 状态与驱动

| 项目 | 值 / 行为 |
|---|---|
| Buff 类型 | `BuffType.BrutalShot = 9` |
| 组件 | `ECS/Components/BuffComponent.cs` 中的 `BuffBrutalShot`，保存 `endTime` |
| 永久状态 | `endTime <= 0` |
| 到期清理 | `BuffBrutalShotSystem.RemoveExpired`，同时移除对应的头顶 Buff 图标 |
| 占位驱动 | 足球模式（`MapType.Bomb`）下，每隔 `10s` 给所有存活的 `UnitType.AIBoss` 挂 `4s` Buff |
| 首次挂载 | 开局后第 10 秒（`nextGrantTime` 初始化为 `BrutalShotInterval`） |
| 图标 | `buff_brutalshot`，通过 `BuffEffectItem` 显示 |
| 进入表现 | `BrutalShotChargeEffect`，0.6s |

行为树节点 `BrutalShotAction` 已存在，支持“冷却到了就给自己挂 Buff”，但当前 `boss_football_3` 没有使用它；后续接入行为树后可删掉占位驱动。

### 3. 触发条件

`RoleKickBombSystem.CheckKick` 中：

1. 被踢的是普通泡泡（不带 `FootballComponent`）；
2. 踢球者带 `BuffBrutalShot`；
3. 踢出方向的紧邻格没有被边界 / 墙 / 门 / 建筑挡住（`AICommonLogic.IsBrutalShotBlocked`）。

紧邻格有阻挡时，不触发抽射，回退到普通踢球（8 格 + 穿屏 + 落点回退）。泡泡、角色、地上的道具都不算阻挡。

### 4. 结算规则

设被踢泡泡所在格为 P，踢出方向为 D，该方向的地图边界为 B。

1. **收集泡泡**：P→B 直线上、满足以下条件的泡泡：
   - `BombState.Normal`；
   - `TryBomb == Success`；
   - `EntityEndTime > 当前时间`；
   - 未销毁。
   飞行中的泡泡不参与。
2. **收集角色**：同一行 / 列、位于 P 与 B 之间的角色（含 P，排除踢球者自己）：
   - 英雄玩家；
   - AI 角色；
   - 分身 Clone；
   - 已死亡角色排除。
3. **排序**：泡泡和角色混在一起，按“距边界距离”从小到大排序。
4. **角色结算**：不再瞬移角色，改为挂减速 Buff：
   - 降低 3 个速度档位；
   - 最低保留 1 档（1 格/秒）；
   - 持续 3 秒；
   - 走通用 `BuffType.SpeedUp` 的负增量实现。
5. **泡泡结算**：从边界向内找第一个可站立格，然后依次向内占格；遇墙 / 砖 / 河 / 门 / 建筑继续向内跳过。
6. 直线之外的实体原地不动。
7. 如果直线范围内没有任何泡泡或角色，直接返回，不播冲击线。

### 5. 方向和边界

| 方向 | 边界 | 向内方向 |
|---|---|---|
| 左 | `x = 0` | `+x` |
| 右 | `x = col - 1` | `-x` |
| 下 | `y = 0` | `+y` |
| 上 | `y = row - 1` | `-y` |

### 6. 泡泡移动细节

- 更新 `GridID` / `Position` / `LastGridID` / `FlyTarget`；
- 从原格 `GetBombs().arr` 移除，加入新格 `arr`；
- `GetBombs().list` 不变；
- 状态重置为 `BombState.Normal`，飞行方向清零，`FlyStep = 0`；
- `TryBomb` 重置为 `Success`，让 `BombChainSystem` 按新格重算连锁关系。

### 7. 表现

| 表现 | 资源 | 说明 |
|---|---|---|
| 蓄力 / 进入状态 | `BrutalShotChargeEffect` | 在角色所在格播放，0.6s |
| 贯穿冲击线 | `BrutalShotLineEffect` | 从泡泡起始格到该方向边界，0.5s |
| 头顶 Buff 图标 | `buff_brutalshot` | 限时 / 永久由 `BuffEffectItem` 控制 |
| 钉墙特效 | `PinToWallEffect` | 资源还在，但当前逻辑已不瞬移玩家，**暂时未使用** |

## 四、足球通用规则

### 1. 球的来源

- 玩家在 `MapType.Bomb` 下不能自己放泡泡（`BombCreateSystem` 直接返回）。
- `BombMapRulesSystem` 每隔 `FootballConstant.CreateInterval = 5s` 落一波球：
  - 取“当前时间已过的最大 `GameTime` 节点”对应的一组配置；
  - 从地图左 / 右边界水平飞入随机空地；
  - Boss 模式进入 `BossModeState.End` 后停止落球。
- 每波还会按地图道具池随机落 1 个道具（有概率不掉）。

### 2. 踢球前提

- 角色 `Alive` 或 `TryTrapped`；
- 有输入方向；
- `CanKickBomb == true`（足球模式下英雄、AI、分身都为 true）；
- 非弹簧跳跃中；
- 目标格**只有 1 颗球**，且 `TryBomb == Success`，并且“未过期或本身是足球”（`CommonLogic.GetKickBall`）。

### 3. 足球的踢出分支

统一入口 `FootballLogic.KickFootball`：

```text
先 RecordKick 记计数
再判断踢出方向紧邻格是否被挡
    计数触发且 TriggerResponse == Fly  → 原始 fly
    被挡且 BlockedResponse == Bounce   → 反方向滑行
    被挡且 BlockedResponse == Fly      → 原始 fly
    未被挡                             → 足球自己的运动
```

- **原始 fly**：8 格 + 穿屏 + 只对落点做障碍回退，由 `BombFlySystem` 推进。
- **足球运动**：抛物线（Arc）或直线减速（Linear），由 `FootballMotionSystem` 推进。
- 两条分支共同的不变量：
  - 踢出即 `RemoveFromGrid` + `RemoveFromList`，飞行途中不占格、不挡人、不挡爆炸波、不可再踢；
  - 落地才 `EnsureInGrid` + `AddToList`，并置 `BombState.Normal` / `TryBomb.Success`；
  - 每次踢出都会把保活时间重置为 `FootballConstant.KeepAliveSeconds = 86400s`，所以足球不会自然到期爆炸；
  - 计数效果统一在 `FootballLogic.OnFootballLanded` 里结算。

### 4. 足球运动

| 类型 | 行为 |
|---|---|
| `Arc + Land` | 抛物线飞向目标格，越界穿屏，接近目标后落地 |
| `Linear + Stop` | 踢出瞬间满速，之后持续减速；撞到东西停住 |
| `Linear + Bounce` | 踢出瞬间满速，之后持续减速；撞到东西原速反向，反弹次数用完才落地 |

- 直线球初速：`14 格/秒`；
- 摩擦力按目标滑行格数反推，调速度时滑行距离不变；
- 反弹不损耗动量，只翻转方向；
- 减速即将停下时，`FootballMotionSystem.TryStopAtFinalCenter` 会预测最终停格，若本帧会越过格心，直接停在格心并落地，避免“冲过格心再弹回”。
- 足球碰撞判定 `FootballLogic.IsGridBlocked` 只把以下内容当障碍：
  - 地图边界；
  - 墙 / 砖 / 河 / 钉子墙 / 图腾 / 活动砖；
  - 门；
  - 建筑；
  - 其它泡泡（不含自己）。
  角色、分身、地上的道具都不阻挡足球。

### 5. 足球免疫

- 足球不会自然引信爆炸（`BombBlowUpSystem` 跳过 `HasFootball`）；
- 同一格同时有普通泡泡和足球时，爆炸流程优先取普通泡泡，不会拿足球当引爆源；
- 不被飞镖引爆（`DartsFlySystem` 跳过足球）；
- 不参与泡泡连锁（`BombChainSystem` 跳过足球）；
- 钉子地板、钉子墙不会引爆足球；
- AI 危险计算忽略足球（`CommonLogic.GetGridDangerTime` 跳过 `HasFootball`）。

补充：

- 踢球要求目标格只有 1 颗球，所以普通泡泡和足球叠在同一格时不能踢；
- 抛物线会越界穿屏；直线球不会穿屏，撞到边界按 `Stop` 或 `Bounce` 处理。

### 1. 计数球-爆炸（200011）

- 阈值：`FootballConstant.TriggerCount = 3`；
- 每次被任意角色踢都 +1，达到 3 后计数立即归 0；
- 触发那一脚照常踢出：
  - 未被挡 → 抛物线；
  - 被挡 → 原始 fly；
- 踢出时：
  - 给泡泡挂 `pendingExplosion`；
  - 在泡泡 View 上挂 `ExplosiveBallChargeEffect`；
  - 按本次预计落点提前生成 13 格预警标记（`mark_1`，`ExplosionWarningMarkId = 1`）；
- 落地时：
  - 以落点为中心生成曼哈顿半径 2 的菱形爆炸波（共 13 格，越界裁掉）；
  - 每格创建普通火焰实体，复用普通泡泡的火焰伤害 / 表现流程；
  - 播放爆炸音效；
  - 预警标记靠时间自然消失。

### 2. 足球-棉花（200012）

- 直线运动，初速 14 格/秒，约滑行 3 格后自然停下；
- 撞到普通泡泡：自身按原速反弹，不损耗动量；
- 最多反弹 3 次；
- 撞墙 / 边界：由 `FootballHitResponse.Bounce` 处理反弹。

### 3. 足球-钢铁（200013）

- 直线运动，约滑行 7 格；
- 撞到普通泡泡：直接引爆对方，自身继续前进；
- 撞墙 / 边界：停下；
- 不会被人挡住。

### 4. 足球-橡胶（200014）

- 直线运动，约滑行 5 格；
- 撞到普通泡泡：先把对方按同方向踢飞 8 格，自身再原速反弹；
- 最多反弹 5 次；
- 撞墙 / 边界：反弹。

## 六、对决球-冰霜（200015）

### 1. 定位

足球 PvE 里的“拔河球”：玩家踢和 Boss 踢会让计数往相反方向走，哪一队把计数推到自己的极限，哪一队就被大幅减速。

### 2. 数值

| 项目 | 值 |
|---|---|
| 初始计数 | 5 |
| 下限 | 0 |
| 上限 | 10 |
| 玩家踢一次 | +1 |
| Boss 踢一次 | -2 |
| 正常踢出滑行格数 | 3 |
| 触发后减速时长 | 3 秒 |
| 触发后减速档位 | 9 档（最低保留 1 档，即 1 格/秒） |
| 触发后是否重置计数 | 是，落地后回到初始值 5 |

推导：

- 玩家需要连续踢 5 次，把 5 推到 10，触发“减速 Boss”；
- Boss 需要踢 3 次，把 5 降到 0，触发“减速玩家”；
- 触发后计数回 5，重新开始拔河。

### 3. 踢球行为

- 正常踢出：直线滑行 3 格；
- 踢出方向紧邻格被挡：**直接反方向滑行**（不是原始 fly）；
- 滑行途中撞到泡泡 / 障碍：按 `FootballHitResponse.Stop` 停下；
- 计数达到 0 或 10 的那一脚：
  - `TriggerResponse = Fly`，本次必定走原始 8 格踢飞；
  - 落地时播放 `IceBreakEffect`（球身上放大 4 倍，全屏级表现）；
  - 结算减速 Buff；
  - 计数回到 5。

### 4. 减速结算

- 计数到 10：减速所有 `TeamEnum.Neutal` 的 AI（Boss）；
- 计数到 0：减速所有 `TeamEnum.Team1` 的英雄；
- 只对 `RoleState.Alive` / `TryTrapped` 且带 `MoveSpeed` 的角色生效；
- 通过 `BuffType.SpeedUp` 的负速度增量实现；
- 最低保留 1 档，不会把速度减到 0。

### 5. 表现

- 球身上显示当前计数（0~10）；
- 接近上限（Boss 将被减速）显示偏绿色；
- 接近下限（玩家将被减速）显示偏红色；
- 其余情况白色；
- 冰霜球自运动时透明度变为 `0.35`。

## 十、注意事项 / 已知差异

1. **暴力抽射不只给哈兰**  
   `BuffBrutalShotSystem` 会给足球模式下所有存活的 `AIBoss` 挂 Buff，因此 1217 / 1218 的普通足球 Boss 也会使用暴力抽射。如果只想让哈兰拥有，需要加地图 / Boss ID 判断。

2. **角色不再被瞬移**  
   早期规格里“把同线玩家吸到边界”已改为“给同线角色挂 3 秒减速”。`PinToWallEffect` 仍然保留，但当前没有调用。

3. **足球没有 0.5 秒踢球冷却**  
   当前 `FootballLogic.CanKick` 只判断“是否处于足球运动中”。落地并重新占格后就可以立刻再踢；旧文档里的 0.5 秒冷却已不存在。

4. **计数球阈值是 3，不是 5**  
   常量位置也变了：`FootballConstant.TriggerCount`，不再在 `BattleConstant` 下。

5. **冰霜球的“反弹”只在踢出瞬间**  
   踢出方向紧邻格被挡时反向滑行；滑行途中撞到障碍 / 泡泡会直接停下，不会继续反弹。

6. **特殊球当前没有全部启用**  
   按 `Xls/xls/BombMap.xlsx` 源表，1219 里 200011~200014 的 `DropBombCount = 0`，只启用了 200015 冰霜球；需要调整数量才会让计数球 / 棉花 / 钢铁 / 橡胶出现。

7. **客户端导出数据需要重新导表**  
   截至 2026-10-26 检查：
   - `Xls/xls/Bomb.xlsx` 已把 200011 配成 `bombType = 4`，并新增 200015；
   - 客户端 `Demo/Assets/Data/Xls/BombRawConfigList.bytes` 仍是旧数据（200011 = 5，且没有 200015）；客户端 `BombMapRawConfigList.bytes` 里 1219 也还是 200011×1 + 普通球；
   - 服务器 `Configs/json` 也还没同步 200011~200015 和 1219 的掉落配置。  
   在重新导表前，当前客户端里的 200011 会被当成棉花球处理，1219 也不会出现冰霜球。

8. **哈兰行为树没有独立内容**  
   `boss_football_3.asset` 与 `boss_football_1.asset` 完全一致；哈兰的差异目前只来自数值和全局暴力抽射驱动。后续如果要做专属技能，需要改行为树并确认对应 `SkillAction` 配置。

9. **录像快照**  
   新增 `FootballComponent` / `FootballMotionComponent` / `BuffBrutalShot` / `BuffEffectItem` 后，需要确认录像快照 Codec 已重新生成并包含这些组件，否则录像中途恢复时计数、运动状态或 Buff 图标可能丢失。
