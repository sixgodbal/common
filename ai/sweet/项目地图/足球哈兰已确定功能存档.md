## 三、暴力抽射（Brutal Shot）

### 1. 定位

- 挂在角色身上的 Buff，不再使用独立的 `BrutalShotComponent`。
- 持有期间，该角色踢**普通泡泡**时不再走普通 8 格踢飞，而是走暴力抽射结算。
- 足球球型（带 `FootballArcMotion` / `FootballLinearStopMotion` / `FootballLinearBounceMotion` 等运动组件的泡泡）不进入暴力抽射分支，仍走足球自己的踢球逻辑。
- 代码里不限制必须是 Boss：任何角色带上 `BuffBrutalShot` 都能触发；当前只有哈兰通过技能 `20000401` 获得。

### 2. 状态与驱动

| 项目 | 值 / 行为 |
|---|---|
| Buff 类型 | `BuffType.BrutalShot = 9` |
| 组件 | `ECS/Components/BuffComponent.cs` 中的 `BuffBrutalShot`，保存 `endTime` |
| 永久状态 | `endTime <= 0` |
| 到期清理 | `BuffBrutalShotSystem.RemoveExpired`，同时移除对应的头顶 Buff 图标 |
| 驱动 | 技能 `20000401`：type 4 范围 Buff，`args = 9,4000`，`autoUse = 1`，`cd = 10s`，`param = filter=Self;shape=1;team=Friend`；由 `SkillAutoCastSystem` 每 10 秒自动释放，给 Boss 自己挂 4 秒 Buff |
| 生效范围 | 只有配了该技能的 Boss（当前仅哈兰 200004）；1217 / 1218 的 Boss 不会获得暴力抽射 |
| 图标 | `buff_brutalshot`，通过 `BuffEffectItem` 显示 |
| 进入表现 | `BrutalShotChargeEffect`，0.6s |

行为树节点 `BrutalShotAction` 仍保留，支持“冷却到了就给自己挂 Buff”，但当前没有任何 Boss 树接入它；既然已改成技能自动释放，后续不需要再接入。

### 3. 触发条件

`RoleKickBombSystem.CheckKick` 中：

1. 被踢的是普通泡泡（没有足球运动组件）；
2. 踢球者带 `BuffBrutalShot`；
3. 踢出方向的紧邻格没有被边界 / 墙 / 门 / 建筑挡住（`FootballLogic.IsBrutalShotBlocked`）。

紧邻格有阻挡时，不触发抽射，回退到普通踢球（8 格 + 穿屏 + 落点回退）。泡泡、角色、地上的道具都不算阻挡。

### 4. 结算规则

设被踢泡泡所在格为 P，踢出方向为 D，该方向的地图边界为 B。

1. **收集泡泡**：P→B 直线上、满足以下条件的泡泡：
   - `BombState.Normal`；
   - `TryBomb == Success`；
   - `EntityEndTime > 当前时间`；
   - 未销毁。
   飞行中的泡泡不参与。
2. **收集角色**：同一行 / 列、位于 P 与 B 之间的角色（含 P，排除踢球者自己）：
   - 英雄玩家；
   - AI 角色；
   - 分身 Clone；
   - 已死亡角色排除。
3. **排序**：泡泡和角色混在一起，按“距边界距离”从小到大排序。
4. **角色结算**：不再瞬移角色，改为挂减速 Buff：
   - 降低 3 个速度档位；
   - 最低保留 1 档（1 格/秒）；
   - 持续 3 秒；
   - 走通用 `BuffType.SpeedUp` 的负增量实现。
5. **泡泡结算**：从边界向内找第一个可站立格，然后依次向内占格；遇墙 / 砖 / 河 / 门 / 建筑继续向内跳过。
6. 直线之外的实体原地不动。
7. 如果直线范围内没有任何泡泡或角色，直接返回，不播冲击线。

### 5. 方向和边界

| 方向 | 边界 | 向内方向 |
|---|---|---|
| 左 | `x = 0` | `+x` |
| 右 | `x = col - 1` | `-x` |
| 下 | `y = 0` | `+y` |
| 上 | `y = row - 1` | `-y` |

### 6. 泡泡移动细节

- 更新 `GridID` / `Position` / `LastGridID` / `FlyTarget`；
- 从原格 `GetBombs().arr` 移除，加入新格 `arr`；
- `GetBombs().list` 不变；
- 状态重置为 `BombState.Normal`，飞行方向清零，`FlyStep = 0`；
- `TryBomb` 重置为 `Success`，让 `BombChainSystem` 按新格重算连锁关系。

### 7. 表现

| 表现 | 资源 | 说明 |
|---|---|---|
| 蓄力 / 进入状态 | `BrutalShotChargeEffect` | 在角色所在格播放，0.6s |
| 贯穿冲击线 | `BrutalShotLineEffect` | 从泡泡起始格到该方向边界，0.5s |
| 头顶 Buff 图标 | `buff_brutalshot` | 限时 / 永久由 `BuffEffectItem` 控制 |
| 钉墙特效 | `PinToWallEffect` | 资源还在，但当前逻辑已不瞬移玩家，**暂时未使用** |

## 四、足球通用规则

### 1. 球的来源

- 玩家在 `MapType.Bomb` 下不能自己放泡泡（`BombCreateSystem` 直接返回）。
- `BombMapRulesSystem` 每隔 `FootballConstant.CreateInterval = 5s` 落一波球：
  - 取“当前时间已过的最大 `GameTime` 节点”对应的一组配置；
  - 从地图左 / 右边界水平飞入随机空地；
  - Boss 模式进入 `BossModeState.End` 后停止落球。
- 每波还会按地图道具池随机落 1 个道具（有概率不掉）。

### 2. 踢球前提

- 角色 `Alive` 或 `TryTrapped`；
- 有输入方向；
- `CanKickBomb == true`（足球模式下英雄、AI、分身都为 true）；
- 非弹簧跳跃中；
- 目标格**只有 1 颗球**，且 `TryBomb == Success`，并且“未过期或本身是足球”（`CommonLogic.GetKickBall`）。

### 3. 足球的踢出分支

统一入口 `RoleKickBombSystem.KickBall`（英雄、AI、分身、暴力抽射都走这里）：

```text
HasBombLandSlow → 先把落地球的减速目标改成「踢球者队伍 + isReverse = true」
CheckTriggerRecord → 计数球 / 对决球记数，满阈值时给球挂落地效果
判断踢出方向紧邻格是否被挡
    计数触发且 TriggerResponse == Fly  → 原始 fly
    被挡且 BlockedResponse == Bounce   → 反方向滑行（冰霜球）
    被挡（其它情况）                   → 原始 fly
    未被挡                             → 有运动组件走足球运动，没有运动组件则原始 fly
```

- **原始 fly**：8 格 + 穿屏 + 只对落点做障碍回退，由 `BombFlySystem` 推进。
- **足球运动**：抛物线（Arc）或直线减速（Linear），由 `FootballMotionSystem` 推进。
- 两条分支共同的不变量：
  - 踢出即 `RemoveFromGrid` + `RemoveFromList`，飞行途中不占格、不挡人、不挡爆炸波、不可再踢；
  - 落地才 `EnsureInGrid` + `AddToList`，并置 `BombState.Normal` / `TryBomb.Success`；
  - 每次踢出都会把保活时间重置为 86400 秒（组件里直接写死），所以足球不会自然到期爆炸；
  - 落地效果统一在 `FootballLogic.OnBombLanded` 里结算。

### 4. 足球运动

| 类型 | 行为 |
|---|---|
| `Arc + Land` | 抛物线飞向目标格，越界穿屏，接近目标后落地 |
| `Linear + Stop` | 踢出瞬间满速，之后持续减速；撞到东西停住 |
| `Linear + Bounce` | 踢出瞬间满速，之后持续减速；撞到东西原速反向，反弹次数用完才落地 |

- 直线球初速：`14 格/秒`；
- 摩擦力按目标滑行格数反推，调速度时滑行距离不变；
- 反弹不损耗动量，只翻转方向；
- 减速即将停下时，`FootballMotionSystem.TryStopAtFinalCenter` 会预测最终停格，若本帧会越过格心，直接停在格心并落地，避免“冲过格心再弹回”。
- 足球碰撞判定 `FootballLogic.IsGridBlocked` 只把以下内容当障碍：
  - 地图边界；
  - 墙 / 砖 / 河 / 钉子墙 / 图腾 / 活动砖；
  - 门；
  - 建筑；
  - 其它泡泡（不含自己）。
  角色、分身、地上的道具都不阻挡足球。

### 5. 足球免疫

- 200011~200015 都挂了 `NoExplosion`：
  - 不会自然引信爆炸（`BombBlowUpSystem`）；
  - 不被飞镖引爆（`DartsFlySystem`）；
  - 不参与泡泡连锁（`BombChainSystem`）；
  - 钉子地板 / 钉子墙不会引爆（`PinFloorRuleSystem` / `BombSlidingSystem`）。
- 200016 随机球没有 `NoExplosion`，不踢时会像普通泡泡一样 3s 自然爆炸，上述免疫都不适用。
- AI 危险计算跳过带 `NoExplosion` 的格子来源（`CommonLogic.GetGridDangerTime`），所以 200011~200015 不算危险物；200016 仍会被当成危险泡泡躲避。

补充：

- 踢球要求目标格只有 1 颗球，所以普通泡泡和足球叠在同一格时不能踢；
- 抛物线会越界穿屏；直线球不会穿屏，撞到边界按 `Stop` 或 `Bounce` 处理。

### 1. 计数球-爆炸（200011）

- 阈值：`FootballConstant.TriggerCount = 3`；
- 每次被任意角色踢都 +1，达到 3 后计数立即归 0；
- 触发那一脚照常踢出：
  - 未被挡 → 抛物线；
  - 被挡 → 原始 fly；
- 踢出时：
  - 给泡泡挂 `pendingExplosion`；
  - 在泡泡 View 上挂 `ExplosiveBallChargeEffect`；
  - 按本次预计落点提前生成 13 格预警标记（`mark_1`，`ExplosionWarningMarkId = 1`）；
- 落地时：
  - 以落点为中心生成曼哈顿半径 2 的菱形爆炸波（共 13 格，越界裁掉）；
  - 每格创建普通火焰实体，复用普通泡泡的火焰伤害 / 表现流程；
  - 播放爆炸音效；
  - 预警标记靠时间自然消失。

### 2. 足球-棉花（200012）

- 直线运动，初速 14 格/秒，约滑行 3 格后自然停下；
- 撞到普通泡泡：自身按原速反弹，不损耗动量；
- 最多反弹 3 次；
- 撞墙 / 边界：由 `FootballHitResponse.Bounce` 处理反弹。

### 3. 足球-钢铁（200013）

- 直线运动，约滑行 7 格；
- 撞到普通泡泡：直接引爆对方，自身继续前进；
- 撞墙 / 边界：停下；
- 不会被人挡住。

### 4. 足球-橡胶（200014）

- 直线运动，约滑行 5 格；
- 撞到普通泡泡：先把对方按同方向踢飞 8 格，自身再原速反弹；
- 最多反弹 5 次；
- 撞墙 / 边界：反弹。

### 5. 随机球（200016）

- 不踢时等同普通泡泡，3 秒引信到点自然爆炸；
- 首次天降落地不结算（`BombLandSafe 1`），被踢出后落地才触发随机效果，触发后立刻消失（`BombLandDisappear`）；
- 随机权重（`FootballLogic.AddComponents`）：

| 索引 | 权重 | 效果 |
|---|---|---|
| 0~3 | 0 | 落地爆炸（半径 1 / 2），权重为 0，不会出现 |
| 4 | 1000 | 落地减速：命中踢球者队伍的反选，-9 档 / 3 秒（实际最低保留 1 档） |
| 5 | 1000 | 西瓜皮 `5007 ×3`（范围 2） |
| 6 | 1000 | 鞋子 `5003 ×2` |
| 7 | 500 | 飞镖 `5009 ×2` |
| 8 | 500 | 陷阱 `5016 ×3` |
| 9 | 200 | 无效果 |
| 10 | 100 | 无效果（原“落地无敌”已注释） |
| 11 | 15 | 叉子 `5008 ×3` + Boss 真实掉落 |

- 落地减速的目标队伍在 `RoleKickBombSystem.KickBall` 里改写为“踢球者队伍 + `isReverse = true`”，球上配的 `TeamEnum.None` 只是占位。

## 六、对决球-冰霜（200015）

### 1. 定位

足球 PvE 里的“拔河球”：玩家踢和 Boss 踢会让计数往相反方向走，哪一队把计数推到自己的极限，哪一队就被大幅减速。

### 2. 数值

| 项目 | 值 |
|---|---|
| 初始计数 | 5 |
| 下限 | 0 |
| 上限 | 10 |
| 玩家踢一次 | +1 |
| Boss 踢一次 | -2 |
| 正常踢出滑行格数 | 3 |
| 触发后减速时长 | 3 秒 |
| 触发后减速档位 | 9 档（最低保留 1 档，即 1 格/秒） |
| 触发后是否重置计数 | 是，落地后回到初始值 5 |

推导：

- 玩家需要连续踢 5 次，把 5 推到 10，触发“减速 Boss”；
- Boss 需要踢 3 次，把 5 降到 0，触发“减速玩家”；
- 触发后计数回 5，重新开始拔河。

> 减速档位在 `AICommonLogic.TriggerBuff` 里 clamp 到最低 1 档；早期版本会降到 0 档，导致 Boss 移速为 0、AI 寻路除零报错，见第十节第 11 条。

### 3. 踢球行为

- 正常踢出：直线滑行 3 格；
- 踢出方向紧邻格被挡：**直接反方向滑行**（不是原始 fly）；
- 滑行途中撞到泡泡 / 障碍：按 `FootballHitResponse.Stop` 停下；
- 计数达到 0 或 10 的那一脚：
  - `TriggerResponse = Fly`，本次必定走原始 8 格踢飞；
  - 落地时播放 `IceBreakEffect`（球身上放大 4 倍，全屏级表现）；
  - 结算减速 Buff；
  - 计数回到 5。

### 4. 减速结算

- 落地 Buff 由 `BombLandSlowComponent` 配置：`targetTeam` + `isReverse` + `type` + `args`；
  - `isReverse = false`：只命中 `targetTeam`；
  - `isReverse = true`：命中 `targetTeam` 之外的所有队伍；
  - 触发时直接调用 `AICommonLogic.TriggerBuff(context, role, type, args)`，不再写死减速逻辑；
- 对决球按“踢球者队伍”反选：
  - 计数到 10（玩家方推满）→ 命中非玩家方（Boss / `Neutal`）；
  - 计数到 0（Boss 方推满）→ 命中非 Boss 方（英雄 / `Team1`）；
  - 当前 Buff 参数为 `SpeedUp`：`args = { SpeedUp, 3000, -9 }`（纯透传，速度档位由 `GetSpeedByIndex` 兜底 clamp）；
  - `args` 由 `FootballLogic.CreateBuffArgs(buffType)` 生成，已支持 `Invicible`（3 秒）/ `SpeedUp`（3 秒，-9 档）/ `BrutalShot`（4 秒）；
- 随机球在踢出时把落地 Buff 的目标改为“踢球者队伍 + 反选”；
- 遍历 `HeroArr` + `AIPlayerArr`，按队伍过滤；
- 只对 `RoleState.Alive` / `TryTrapped` 且带 `MoveSpeed` 的角色生效。

### 5. 表现

- 球身上挂 `bomb_item_vs` 预制体显示对战计数（见第七节）；
- `txt_left` 显示玩家侧计数（`count`，0~10）；
- `txt_right` 显示 Boss 侧计数（`maxCount - count`，即 `10 - count`）；
- 例：当前 `count = 7` → 左边 7、右边 3；
- 左右文字颜色由预制体自身配置，代码不再按高低改色；
- 冰霜球自运动时透明度变为 `0.35`（只影响球身，不影响预制体）。

## 十、注意事项 / 已知差异

1. **暴力抽射现在只给哈兰**  
   已由“所有 AIBoss 占位驱动”改为技能驱动：只有 `Boss.xlsx` 里配了 `20000401` 的哈兰会获得，200002 / 200003 的 `skills` 为空，不再拥有暴力抽射。

2. **角色不再被瞬移**  
   早期规格里“把同线玩家吸到边界”已改为“给同线角色挂 3 秒减速”。`PinToWallEffect` 仍然保留，但当前没有调用。

3. **足球没有 0.5 秒踢球冷却**  
   当前 `FootballLogic.CanKick` 只判断“是否处于足球运动中”。落地并重新占格后就可以立刻再踢；旧文档里的 0.5 秒冷却已不存在。

4. **计数球阈值是 3，不是 5**  
   常量位置也变了：`FootballConstant.TriggerCount`，不再在 `BattleConstant` 下。

5. **冰霜球的“反弹”只在踢出瞬间**  
   踢出方向紧邻格被挡时反向滑行；滑行途中撞到障碍 / 泡泡会直接停下，不会继续反弹。

6. **特殊球当前启用情况**  
   按 `Xls/xls/BombMap.xlsx` 源表，1219 里 200011~200014 的 `DropBombCount = 0`，实际只启用 200015 冰霜球（0s ×1）和 200016 随机球（5s ×1、10s ×2）；需要调整数量才会让计数球 / 棉花 / 钢铁 / 橡胶出现。

7. **导表与同步状态**  
   2026-11-07 已重新导表并同步：
   - `Xls/xls/Bomb.xlsx` 含 200011~200016（200011 = `bombType 4`）；
   - 客户端 `Demo/Assets/Data/Xls/BombRawConfigList.bytes`、`BombMapRawConfigList.bytes` 已是新数据（1219 见第八节）；
   - 服务器 `Configs/xls` 已同步；`Configs/json` 里的 Bomb 两张表仍是 2026-10-24 旧数据，但服务器 `ConfigSvc` 不加载它们，不影响开战。

8. **哈兰已有专用行为树**  
   `boss_football_halan_1.asset`（2026-11-07 新增）含 `FindKickDuelBallAction`、`FindKickBallToDangerAreaAction`、`HasTrappedPlayer`、`DoMoveStop`、`IsDangerGridConditional`、`DoEmo`、`SkillAction 2003`（受伤丢胶）等节点；`boss_football_3.asset` 仍在但已无 Boss 引用。

9. **录像快照**  
   新增 `FootballMotion` / `FootballKickSetting` / `FootballCounter` / `FootballDuel` / `BombLand*` / `BuffBrutalShot` / `BuffEffectItem` 后，需要确认录像快照 Codec 已重新生成并包含这些组件，否则录像中途恢复时计数、运动状态或 Buff 图标可能丢失。

10. **计数 UI 的尺寸位置在预制体上调**  
    `bomb_item_counter.prefab` / `bomb_item_vs.prefab` 根节点当前 `scale = 1`、`RectTransform` 尺寸约 `126 × 50`，作为 World Space Canvas 直接挂到泡泡上会偏大；代码（`BombItem_Counter` / `BombItem_VS`）只负责挂父节点和刷新文字，不覆盖 Transform，位置和缩放需要在预制体里调。

11. **减速到 0 档会让 AI 寻路除零（2026-11-07 已修复）**  
   - 触发链：冰霜球计数到 10 / 0 → 落地减速 `-9` 档 → 7 档的 Boss 变成 `-2` 档 → `GetSpeedByIndex` clamp 到 0 档 → `speed_table[0] = 0` → `BuffSpeedSystem` 把 0 写进 `MoveSpeed` → `FindPathAction` 取速度 0 → `MoveTimeLogic.IFMoveto` 除以 0 → `Fix.op_Division` 抛 `System.Exception`；异常从行为树冒到 `NetService.HandleReceive`，该帧后续处理（含 `RecordLogicFrame`）被跳过。
   - 修复：`AICommonLogic.TriggerBuff` 的 `SpeedUp` 分支把目标档位 clamp 到 `[1, 10]`，真正实现“最低保留 1 档”；`MoveTimeLogic.IFMoveto` 增加 `dt_speed == 0` 保护，直接返回不再除零。

12. **落地减速的目标队伍是运行期改写的**  
    `RoleKickBombSystem.KickBall` 在踢出瞬间把 `BombLandSlow.targetTeam` 设为踢球者队伍、`isReverse = true`；`FootballLogic.AddComponents` 里写的 `TeamEnum.None` 只是占位，不代表实际命中对象。

13. **对决球计数只在“触发后的落地”重置（2026-11-07 修复）**  
    之前 `OnBombLanded` 每次落地都把 `duel.count` 重置回 `initialCount`。冰霜球每踢一脚都会落地，计数只能 `5 → 6 → 5`，永远到不了 0 / 10，`duelTriggered` 始终为 false，`KickBall` 里按 `FootballTriggerKickType` 强制踢飞的分支也就不会执行。现在的判定只用对决组件自身数据：落地时 `count >= maxCount || count <= minCount` 说明这一脚是触发踢，才重置回 `initialCount`；未触发时计数保留。触发那一脚按 `Fly`（8 格 + 穿屏）踢出，落地施加减速后计数回到 5。
