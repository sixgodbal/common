# MIDI 转换器 开发文档

## 目录结构

```
MIDI转换器/
├── MIDI转换器.pyw   入口：tkinter 界面、拖放、后台任务
├── engine.py        核心：MIDI 解析、DLS 合成、音频编解码
├── icon.ico         窗口图标
├── config.json      配置（首次运行生成，仓库里带一份默认值）
├── README.md        用户说明
├── 开发文档.md      本文件
├── 启动.bat
└── 安装依赖.bat
```

依赖：`numpy`（合成必需）、`soundfile`（FLAC/OGG 和音频读取）、`lameenc`（MP3 编码，缺少时退回 soundfile）。

## 整体流程

```
拖入文件
  │
  ├─ .mid/.midi/.rmi/.kar → parse_midi() → Synth.render() → numpy 波形 → encode_audio()
  │                                            ↑
  │                                   DLSBank（gm.dls）
  │
  └─ 其它音频 → soundfile.read() → resample() → encode_audio()
```

界面线程只负责窗口和交互；转换在 `threading.Thread` 里执行，结果通过 `queue.Queue` 回到主线程，
由 `root.after()` 轮询。任何时候都不要在工作线程里碰 tkinter。

## UI 结构（MIDI转换器.pyw）

窗口固定 `200×200` 逻辑像素（按 DPI 缩放，`ui_scale()`），布局用 `place()` 精确到像素：

- `Canvas` 虚线框：绘制提示文字/文件名，负责点击选择和双击转换
- 两个 `ttk.Combobox`：输出格式、质量
- `tk.Button`：转换
- `tk.Label`：状态行；左键打开输出目录，右键看详情

`FORMATS` 里集中定义格式、扩展名、质量档位和默认值，新增格式时改这里和 `engine.encode_audio()` 即可。
配置按「每种格式记住各自质量」保存，切换格式不会串档。

### 原生拖放

没有用 `tkinterdnd2`，而是直接挂 Windows 的 `WM_DROPFILES`：

1. 用 `DragAcceptFiles(hwnd, True)` 标记窗口接受拖放
2. 用 `SetWindowLongPtrW(hwnd, GWLP_WNDPROC, new_proc)` 子类化窗口过程
3. 在子类化过程里处理 `WM_DROPFILES`：`DragQueryFileW` 取路径 → `DragFinish` → 回调
4. 其余消息原样交给 `CallWindowProcW`
5. 关闭时恢复旧过程并 `DragAcceptFiles(hwnd, False)`

要点：

- Tk 的顶层框 `wm_frame()` 和客户区 `winfo_id()` 都挂一遍，鼠标落在标题栏/客户区都能接
- 64 位下 `SetWindowLongPtrW` / `CallWindowProcW` 必须设置 `argtypes/restype`，否则指针会被截断
- `WNDPROC` 回调对象必须用 Python 变量一直引用，否则会被回收
- 回调运行在 Tk 主线程（Windows 消息循环里），可以直接改控件
- 测试时可以用 `GlobalAlloc` 手工构造 `DROPFILES` 结构，再 `PostMessage(hwnd, WM_DROPFILES, hDrop, 0)` 模拟拖放，不必真拖

## MIDI 解析（engine.parse_midi）

自己实现的 SMF（标准 MIDI 文件）解析，不依赖 mido：

- 支持 format 0/1/2，支持 running status
- 支持 `MThd` / `MTrk`；`.rmi` 先拆 RIFF `data` 块
- 记录所有轨道事件后按 `(tick, 事件序号)` 排序
- 收集 tempo（`FF 51 03`），用二分查找把 tick 换算成秒；支持 SMPTE 时间格式
- 音符配对：每个 `(channel, note)` 一个栈，处理同音重复触发
- 延音踏板 CC64：踏板按下时只标记 note-off，踏板松开时统一结束
- 弯音：记录每个通道的 `(秒, 半音)` 事件，RPN 0/0 改弯音范围
- 音色：CC0 选 bank，Program Change 选音色；通道 10 当作鼓
- 音量 CC7、声像 CC10、表情 CC11 在 note-on 时取快照（不做整段自动化）
- CC120/123 全部音符关闭；文件结束时强制收掉悬挂音符

注意：CC11/CC7 的后续变化不会影响已经发出的长音，这是刻意的简化；游戏 BGM 和大多数普通 MIDI 听不出问题。

## DLS 音色库（engine.DLSBank）

`gm.dls` 是 RIFF/DLS Level 1：

- `LIST lins` → 235 个 `LIST ins` 乐器
- `insh`：区数、bank、program；bank 最高位为 1 表示鼓组
- `LIST lrgn` → `LIST rgn` 区域：`rgnh` 键范围/力度范围，`wsmp` 采样参数，`wlnk` 波表索引
- `LIST wvpl` → 495 个 `LIST wave`：`fmt ` + 16 位 PCM `data`
- `wlnk` 的 table index 直接对应第 n 个 wave（gm.dls 的顺序一致）
- 采样率 22050 或 24000，单声道
- `wsmp` 的循环点：从 `wsmp+20` 读 4 个 DWORD（cbSize、type、start、length）
- `wsmp` 的 `lAttenuation` 和 `art1` 的 `lScale` 都是 16.16 定点、单位 1/100 dB（除以 6553600 得到 dB）
- `art1` 里只取 `source = 0` 的静态连接：`0x0104` 增益、`0x0105` 声像；包络/LFO/滤波没有实现

鼓组音色：`bank & 0x80000000`，program 就是鼓组编号（0 = Standard）；按 key/velocity 找区域，不做移调。

## 合成器（engine.Synth）

每个音符离线生成一段 numpy 波形，再混到总线上：

1. 按 key/velocity 选区域和采样
2. 音高比 = `2 ** ((key - unity + fine/100) / 12) * sample_rate / out_rate`
   - 鼓不跟 key 移调，只应用 fine
3. 采样循环：把超过循环起点的位置 `loop_start + (pos - loop_start) % loop_len` 折回去；
   循环边界处第二个插值点也折回 `loop_start`，避免接缝爆音
4. 线性插值取波形（numpy 向量化）
5. 包络按 GM 音色族给不同的 attack/release/decay：
   - 钢琴/吉他/贝斯：循环起点之后继续指数衰减，否则长按会变成风琴
   - 弦乐/管乐/铺底：长音保持，松键后淡出
   - 鼓：one-shot，采样放完就结束
6. 增益 = 力度^1.5 × 通道音量^1.5 × 表情 × 10^(区域增益/20)
7. 声像用等功率曲线；gm.dls 是单声道，左右各乘 `sqrt(2)` 保持中间音量
8. 全部混完后只在峰值 > 1 时整体压到 0.98，不做响度归一化
9. 首尾 10ms 淡入淡出，避免爆音

性能：30 秒、约 600 个音符的 MIDI 合成约 0.3 秒；75 秒的曲子约 0.7 秒（不含 MP3 编码）。

### 已知的近似

- 没有实现 DLS 的 EG1/EG2、LFO、滤波器和力度→滤波调制；包络是按 GM 音色族估的
- 不支持 SoundFont / FluidSynth / VST；音色就是系统 `gm.dls`
- 鼓通道固定为 10；GS/XG 的多鼓通道、SysEx 主音量、混响深度都不处理
- 有损格式互转会二次压缩

## 音频转码（engine.audio_to_audio / encode_audio）

- 用 `soundfile.read(..., always_2d=True)` 读入，统一转 float32
- 超过 2 声道取平均降为单声道
- 采样率转换优先 `scipy.signal.resample_poly`，没有 scipy 时退回线性插值
- 输出：
  - WAV：标准库 `wave`，16 位 PCM，分块写入
  - MP3：`lameenc`，128/192/320 kbps；`lameenc` 缺失时用 libsndfile 的 MP3 编码兜底
  - FLAC/OGG：`soundfile.SoundFile`，`compression_level` 0.2/0.5/0.6/0.9
  - FLAC 会保留 24 位 / 32 位浮点源的位深（写 PCM_24）；MIDI 输出用 PCM_16
- libsndfile 的 Vorbis 编码器一次性写入超长数组会爆栈，FLAC/OGG/MP3 都要分块写；
  FLAC/OGG 每块 8192 帧，MP3 每块约 100 万帧
- MP3 输出采样率限制在 LAME 支持的集合（8k～48k）；超出范围降到 48k 或升到 44.1k

## 输出命名

`unique_output_path()`：

- 默认 `原目录/原文件名.新扩展名`
- 和源文件同路径（例如 wav→wav）时用 `原文件名 (转换).扩展名`
- 已存在时依次尝试 ` (1)`、` (2)`……
- 永远不覆盖已有文件

## 测试方法

### 1. 命令行验证合成

```python
import engine
engine.convert_file(r"D:\test.mid", r"D:\test.mp3", "mp3", "192")
```

检查：输出时长 ≈ MIDI 时长 + 2 秒尾音、峰值 ≤ 1、没有全静音。
可以用 `soundfile.info()` 看采样率/声道/时长，用 `numpy` 算 RMS/峰值。

### 2. 音高检查

用 mido 生成单音 MIDI（C4/E4/G4/C5），渲染后对 onset 段做 FFT，峰值应分别接近
261.6 / 329.6 / 392.0 / 523.3 Hz。注意分析窗口不要跨到下一个音。

### 3. 音色覆盖检查

生成 128 个 program 各一个 C4 的 MIDI，逐个片段算 RMS，确认没有静音的音色；
鼓组 key 27–87 同理。`gm.dls` 的 128 个 GM 音色都应该有输出。

### 4. 拖放测试

不真拖也能测：

```python
# 构造 DROPFILES 放进 GlobalAlloc，然后 PostMessage(hwnd, WM_DROPFILES, h, 0)
```

`ui_test` 里对客户区和外层 frame 各发一次，确认两条路径都能收到。

### 5. 格式矩阵

用 5 秒 48k 立体声 WAV 做源，分别转 MP3/WAV/FLAC/OGG，再把每种结果转一遍，
检查没有崩溃、时长一致、声道/采样率符合预期。

### 6. 边界

- 空 MIDI / 损坏 MIDI → 提示「MIDI 里没有可播放的音符」
- 文本文件改名 .mp3 → 提示「无法读取音频文件」
- 96k 音频 → MP3 自动降到 48k
- 6 声道 → 单声道输出
- 中文/空格路径 → 正常

## 修改时注意

- `gm.dls` 的解析对 chunk 对齐很敏感：每个 chunk 之后要 `+ (size & 1)`
- DLS 的 `LIST` 类型自带 4 字节类型名，递归子块时从 `body + 4` 开始
- `fine` 在 `wsmp` 里是无符号 WORD，需要手动转成有符号（>= 32768 减 65536）
- `art1` 的增益/声像单位是 1/6553600 dB，不要当成立即数
- 拖放子类化后，所有非 `WM_DROPFILES` 消息都必须交还旧过程，否则窗口按钮/拖动会坏
- 编码器分块写入，别改回一次性 `soundfile.write()`（OGG 会爆栈）
