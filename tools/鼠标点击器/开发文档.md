# 鼠标点击器 · 开发文档

面向后续维护者。使用说明见 `README.md`。

## 基本信息

- 入口：`鼠标点击器.pyw`（单文件，Python 3.8+ / tkinter / pynput）
- 版本：1.0
- 数据：同目录 `config.json`（设置）和 `macros/<id>.json`（每个宏一个文件）
- 日志：`logs/error.log`（启动失败、回调异常才会写入）
- 外部依赖：`pynput`（`pip install pynput`）；图标生成用过 Pillow，但运行时不依赖 Pillow

单文件是刻意的：整个目录拷走、右键 .pyw 建快捷方式就能用，不需要虚拟环境或安装包。

## 代码分区

文件按下面的顺序排列，搜索分节注释即可跳转：

1. **环境 / 日志**：`setup_logging()`、`enable_dpi_awareness()`
2. **配色 / 字体**：`BG` 等常量、`setup_fonts()`、`setup_style()`
3. **配置**：`DEFAULT_SETTINGS`、`normalize_config()`、`load_config()`
4. **宏数据 / 键位**：`sanitize_event()`、`sanitize_macro()`、`key_event_payload()`、`to_pynput_key()`、`build_python_script()`
5. **全局输入**：`InputHub`（全局键盘钩子 + 快捷键 + 注入标记）
6. **引擎**：`Recorder`、`Clicker`、`Player`
7. **通用控件**：`FlatButton`、`Pills`、`Card`、`TabBar`、`CountdownToast`
8. **主窗口**：`App`（四个页面 + 持久化 + 状态机）
9. **对话框**：`ModalDialog`、`InputDialog`、`HotkeyDialog`、`MergeDialog`、`EventEditDialog`、`MacroEditor`
10. **入口**：`main()`

## 线程模型（重要）

Tk 只能在主线程操作。所有后台线程（pynput 监听、连点、回放）都不直接碰控件，而是：

- 引擎线程 → `App.post(fn)` → `queue.Queue`
- Tk 主线程 `_pump()` 每 25ms 取出回调执行
- 快捷键监听线程 → `InputHub._emit(action)` → 同样进入队列 → `App._on_global_action()`

所以全局快捷键的响应上限约 25ms。`F9` 也走这条路，足够快；不要改成在监听线程里直接启动/停止引擎，会引入跨线程 Tk 调用。

## InputHub

全局键盘监听始终开着；鼠标监听只在录制时开（`App._begin_recording`）。

关键字段：

- `hotkeys`：`{"f6": "click", "f7": "record", "f8": "play", "f9": "stop"}`
- `recorder`：当前 `Recorder`；`None` 表示没在录制
- `injecting` / `_last_inject`：防止回放/连点注入的按键再次触发快捷键或被录进宏
- `_pressed_raw`：物理按键按下集合，用于过滤系统自动重复（按住 F6 不会反复开关）
- `_capture`：修改快捷键时的“捕获下一个组合键”回调

### 按键归一化

- `raw_key_name()`：pynput 原始名（`ctrl_l`、`char:a`、`vk:65`）
- `normalize_key_token()`：修饰键归一（`ctrl_l` → `ctrl`，`cmd` → `win`）
- 组合键格式：`ctrl+alt+shift+win+主键`，主键顺序固定
- 单键热键只允许 `F1`～`F24`（`normalize_combo` 和 `_apply_hotkey` 双重限制），避免打字时误触发；其它键必须带修饰键
- `F9` 紧急停止固定，不允许被其它功能占用

### 注入抑制

`Player`/`Clicker` 每次调用 pynput 控制器前后包 `hub.begin_inject()` / `hub.end_inject()`。
监听回调里 `is_injecting()` 为真就忽略事件（同时有一个 30ms 的余量，覆盖钩子回调延迟）。

例外：`F9` 在注入期间仍然会触发停止。这是刻意留的安全口；也意味着如果宏本身录了 F9，回放会自己停下。

### 录制与快捷键

`_on_press()` 的顺序：

1. `F9` 直接停止
2. 如果正在“捕获快捷键”，处理捕获，不录
3. 注入中 → 忽略
4. 系统重复 → 忽略
5. **修饰键**：录制时写入（否则 Ctrl+C 会只剩 C），然后返回
6. 组合键命中工具快捷键 → 执行动作，**不写入宏**
7. 其它按键 → 写入录制

注意：第 5 步是踩过的坑。早期版本在修饰键处直接 `return`，导致所有 Ctrl/Shift/Alt 组合键录制后都丢了修饰键。

停止录制时的 `_clean_recorded_events()`：

- 如果是从界面点“停止录制”按钮停的，删除结尾落在本窗口内的那次点击（否则会把停止按钮的点击录进去）
- 删除结尾 600ms 内的修饰键残留（例如 `Ctrl+F7` 停止时已经按下的 Ctrl）
- 注意只处理结尾；不要全局删除修饰键，否则组合键宏会坏

## Recorder

事件是一个扁平列表，按 `t`（相对开始时间的毫秒数）排序：

```json
{"t": 123.4, "type": "move", "x": 640, "y": 360}
{"t": 200.0, "type": "button", "x": 640, "y": 360, "button": "left", "pressed": true}
{"t": 220.0, "type": "scroll", "x": 640, "y": 360, "dx": 0, "dy": -1}
{"t": 300.0, "type": "key", "pressed": true, "key": "ctrl"}
```

- 鼠标移动只在离上一个记录点 ≥ `record_sample_px` 像素时记录，避免高频鼠标把文件撑爆
- 点击/滚轮会更新“上一个移动点”，所以点击位置不会被重复的 move 覆盖
- 键盘按键用 pynput 的 `Key` / `KeyCode`：特殊键存 `key`，普通字符存 `key`/`vk`/`text`；回放优先用 `vk`，没有 vk 才用字符
- 按键自动重复由 `InputHub._pressed_raw` 过滤（按住 F6 不会反复开关）；`Recorder.down_keys` 负责维护按键按下/松开的配对
- 录制时最小化后是否恢复由 `_rec_restore_on_stop` 决定：从本窗口/前台启动才恢复；在其它程序里按 `F7` 启动的录制结束后保持最小化，避免打断当前工作
- 上限 `MAX_RECORD_EVENTS = 150000`；达到上限后 UI 的 `_tick_live()` 会自动停止并保存
- `stop()` 返回事件快照和时长；录制时长取最后一条事件的 `t`（不是墙上时间）

时间轴**不在加载时归零**。`sanitize_macro()` 保留事件原始 `t`，所以第一段操作前的等待也会保留；编辑器可以把第一段延后/提前。

## Clicker

一个线程，循环：

```
（固定坐标时先移动）
按下 → 松开（双击再等 60ms 按一次）
计数、节流通知 UI
等待 interval（用 Event.wait，便于立即停止）
到次数上限则退出
```

- 固定坐标：每次点击前 `mouse.position = (x, y)`
- 跟随鼠标：不设置位置
- 停止后由 App 清空 `self.clicker`；迟到的回调通过身份比较忽略
- 自然结束/手动停止都会调用 `on_done`，UI 恢复点击次数和窗口

## Player

按事件 `t` 用 `perf_counter()` 定时回放：

- `lead_ms`：开始前等待（给窗口切换留时间）
- `speed`：总时间除以速度
- 如果落后超过 250ms，整体调整 `loop_start`，避免后面一串事件“追赶式”快速执行
- 每 100ms 最多通知一次进度
- **finally 必须释放所有按住的键/按钮**（`_release_all`）。中途停止、异常、宏结束时都不能把 Ctrl/Shift 留在按下状态
- 循环之间等 `gap_ms`；无限循环直到 `F9`

### 回放时最小化

`play_minimize` 默认开。只有本窗口在前台时才会 `iconify()`（用 `_is_foreground_window()` 判断），这样从其它程序按 F8 不会莫名把窗口收起来。回放结束后恢复。

## 宏编辑

`MacroEditor` 操作的是宏事件的深拷贝，点“保存”才写文件。

- 删除：只删这一条，其它事件时间不变
- 提前/延后：选中事件及之后的所有事件整体平移，保持后续间隔
- 修改：`EventEditDialog` 修改字段；时间以“距上一个事件”的毫秒数输入，保存时把选中及之后的事件平移相同差值
- 上限 `LIMIT = 20000` 行（Treeview 性能）；超出部分仍会原样保存，只是不显示
- 关闭有未保存修改时会询问

## 存储

- `config.json`：`write_json_atomic()` 先写 `.tmp` 再 `os.replace`
- 宏文件名 = `macro["id"] + ".json"`，id 用 `uuid4().hex[:12]`，导入冲突时重新生成
- 文件坏了：配置会备份成 `config.json.broken` 并生成默认值；宏读取失败只写日志并跳过
- 宏名称可以中文，但导出文件时用 `safe_filename()` 去掉非法路径字符

## UI 结构

- `App` 继承 `tk.Tk`，四个页面用同一网格 `tkraise()` 切换
- 自定义 `FlatButton`（Label 模拟按钮）、`Pills`（胶囊单选）、`Card`（白卡片）、`TabBar`
- 状态刷新集中在 `refresh_states()`：状态胶囊、按钮文字/颜色/可用状态、最近录制按钮
- 连点/录制/回放/倒计时四个状态互斥，进入某个状态前先看 `_states()`
- 录制页面实时计数在 `_tick_live()` 里更新（5Hz），不要在每个鼠标事件里刷新 UI

## 与“不要抢前台”有关的测试方法

仓库根目录 README 已经写明：开发测试时尽量不要把界面弹到最前面。建议：

- 测试脚本里 patch `App.deiconify`（先 `geometry("+5000+5000")` 再 deiconify）、`App.focus_force`、`App._clamp_window`、`Toplevel.focus_force`
- patch `InputHub.start = lambda self: None`，避免测试期间真实键盘触发 F6/F7/F8，误启动连点/录制
- 用 `PrintWindow`（`user32.PrintWindow` + `CreateDIBSection`）截图，不需要把窗口置顶或激活
- 需要真正显示时再去掉 patch；不要用 `SetForegroundWindow` 或 `focus_force` 做测试

## 测试

本机验证过（测试脚本放在临时目录，不进工具目录）：

1. `python -m py_compile 鼠标点击器.pyw`
2. InputHub：单键/组合键触发、注入期间 F9、快捷键捕获、录制时快捷键不入宏
3. Recorder：移动采样、点击/滚轮、修饰键+普通键、时间戳
4. Clicker：用假 Controller 替换 `pynput.mouse.Controller`，验证固定坐标、次数、双击
5. Player：用假 Controller 验证鼠标/键盘/滚轮调用、循环、停止后释放按住的键
6. 对话框：EventEditDialog 字段回调、MacroEditor 删除/平移/保存、MergeDialog
7. 几何检查：`update_idletasks()` 后确认所有子控件 `y + height` 不超过父容器，防止内容被裁掉

手工冒烟测试（在没有重要工作的桌面上做）：

- 连点：间隔 500ms、无限、跟随鼠标，F6 开始/F9 停止
- 录制：F7 → 移动鼠标、点一下空白处、按 Ctrl+C → F7 停止；检查宏里的 Ctrl/按键顺序
- 回放：选中宏、F8；确认结束后没有卡住 Ctrl/Shift
- 紧凑按键：修改快捷键窗口里按 A，应提示单键只支持 F1～F24；按 Ctrl+Alt+R 应成功
- 关闭时如果正在录制，应询问是否丢弃

## 常见坑

- **修饰键漏录**：见 `InputHub._on_press` 第 5 步
- **回放卡键**：`Player._release_all` 必须在 `finally` 里；不要只在正常结束时释放
- **停止按钮被录进宏**：`_clean_recorded_events()` 依赖 `from_ui=True`；F7/F9 停止不要传 True
- **全局快捷键误触**：单键只允许 F 键；不要开放单字母
- **F9 当宏的一部分**：回放会自我停止；不改，因为安全优先
- **Tk 跨线程**：任何 `configure/text/after` 都要回主线程；`after` 本身也不是线程安全的
- **DPI**：当前用 `SetProcessDpiAwareness(1)`（系统 DPI 感知），与同目录其它工具一致。混合 DPI 多屏下固定坐标可能偏移，README 已说明
- **单实例**：没有做互斥；同时开两个会双份响应快捷键
- **pynput 生命周期**：`Listener.stop()` 后不要再 `start()` 同一个对象；每次录制都新建鼠标 Listener
- **宏列表排序**：按 `created_ts` 倒序；追加/合并后把 `created_ts` 更新为当前时间，让刚改过的宏浮到上面
